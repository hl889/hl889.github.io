产品能力

从一根线接入，到一张图决策

四件事按现场顺序排好：先纳管，再采集，然后让数据自己触发动作，最后落到人看得懂的界面上。

设备接入与建模

把不同厂家的表计、PLC、传感器登记成统一的设备模型：一份型号定义管点位，一份分组管理现场。接入一台和接入一千台，是同一套操作。

设备台账点位映射批量导入

边缘采集

采集策略下沉到网关：按周期轮询、变化上报、异常补传。链路中断时数据先落本地，恢复后按序回补，不让关键点位出现空洞。

周期轮询断点续传数据清洗

规则与联动

用「条件—动作」描述业务：点位超限、设备离线、累计量越界，都能触发通知、工单或反向下发控制。规则可预览、可停用、可回溯触发记录。

阈值告警多条件组合反向下发

数据与看板

时序数据统一落库，按设备、分组、时间切片出图。看板支持曲线、累计、对比与地图位置，也能以整块面板的形式嵌进既有业务系统。

时序存储自定义看板导出报表

分层架构

采集、治理、应用，各归各层

平台按四层切开：换协议只动接入层，换业务只动应用层，中间的数据模型与规则不用跟着改。

边缘层可以按站点拆开部署，一台网关就能独立承担一个现场。

平台层不绑定具体协议，接入层新增协议不影响已有的设备模型。

应用层只读平台层的接口，换前端界面不必回头改采集逻辑。

部署形态

数据放在哪，决定怎么部署

三种形态不是三个版本，而是同一套代码的三种落点；设备模型、规则语法与看板配置在形态之间可以直接带走。

起步常用

公有云托管

开通即用，不必自备服务器与运维人力。适合刚起步的试点，以及设备分散在多个站点、没人长期值守机房的情况。

  • 按设备数量配置资源，随规模弹性调整
  • 升级、备份与证书由平台侧负责
  • 数据出内网前需要先过一轮合规评估
数据不出机房

私有化部署

整套服务部署在客户自己的服务器上，设备数据不经过公网。适合对数据边界有明确要求的生产环境与政企项目。

  • 一台 Linux 服务器即可起步，可做双机
  • 提供离线安装包，内网环境也能安装升级
  • 可与内网既有的业务系统、数据库直连
现场独立运行

边缘单机

单台网关承载一个小规模现场，链路中断时采集与告警继续在本地跑，不必等中心恢复。

  • 千级点位以内的小现场足够用
  • 本地看板与本地告警，不依赖云端
  • 联网后按序把数据同步回中心平台

应用场景

四个现场，同一套底座

换场景时重叠的是接入、存储与联动逻辑，改的只是设备模型和看板布局。

智慧农业

温室、水肥、气象三类设备按棚分组，温湿度越限自动提醒，灌溉与通风按条件联动手动或自动执行。

  • 按棚、按批次追溯环境曲线
  • 水肥机远程启停与用量累计

工业设备

采集产线设备的运行状态、电流与节拍，统计开机率、停机时长与能耗，异常先由规则判定再派人。

  • OEE 基础数据自动汇总
  • 停机原因按规则归类

能源计量

电、水、气、热集中抄表，分项计量落到回路与班组，越限与突增在当天就推给责任人。

  • 分时用量与同期对比
  • 抄表失败自动重试并留痕

园区与楼宇

空调、照明、水泵统一纳管，按楼层与时段分组排程；巡检异常可一键生成工单，回填后闭环。

  • 定时与联动两种控制方式
  • 设备与工单双向追溯

实施路径

从一台设备到一张网，分四步走

每一步都能单独收口，不必等整套平台搭完才看到效果。

第 1 天

试点接入

挑一台正在运行的设备，接上网关、登记点位，确认数据能稳定上行。链路与协议的问题在这一步暴露，代价最低。

第 1 周

模型与看板

按型号整理点位定义与分组，先搭一屏现场看得懂的看板。把“看得见”做实，后面讨论告警和控制才有依据。

第 2–3 周

规则与联动

把现场真正会发生的异常写成规则，配上通知与工单；再挑一到两条控制做联动，顺带验证下行链路。

持续

复制与复盘

按型号批量复制设备，按站点复制看板；每月复盘告警量、误报率与数据缺口，再决定下一步扩到哪个现场。

这是常见的实施节奏，实际周期取决于现场规模、设备厂家的配合度与网络条件。

常见问题

上线前最常被问到的几件事

需要自己准备服务器吗？
三种形态可选：公有云托管、部署在客户内网的私有化实例，或以单台边缘网关承载小规模现场。选哪种取决于现场规模、是否需要与内网系统互访，以及数据能否出内网。
厂家私有协议怎么接？
先用抓包与调试工具确认报文结构，再在平台里按点位表定义地址、类型与换算规则，生成解析模板。同一型号的设备复用同一份模板，后续新增设备只需填地址。
数据能保存多久？
按点位与采样频率分别配置保留策略：关键点位长期留存，高频过程量做降采样归档。也可以对接客户已有的时序库或对象存储，平台只负责采集与查询编排。
能和现有系统打通吗？
开放 REST API 与消息订阅（MQTT / WebSocket），设备状态、点位数据和告警事件都能推给第三方系统；反向控制同样走接口，权限按设备分组划分。
现场断网了会怎样？
采集与缓存留在网关侧，链路恢复后按时间顺序补传；平台会标注数据缺口的时间段，看板与报表不会把缺口当成零值来算。

先接一台设备，
再决定要不要接一千台。

用现场已经跑着的一台表计或传感器做试点，一天之内就能走完接入、采集、规则和看板的完整链路。
